# Koe — launch film

A 42-second, 3840×2160, 30 fps launch film for Koe, made with the plush-crew
storyboard engine (`bs-plush-crew-launch-video`). Five scenes inside a fake
"Koe in 40 seconds" editor, with a five-crew bot cast reacting in the chat column.

- **`koe-en-4k.mp4`** — the delivered film (42.00 s, H.264 4K + AAC 48 kHz stereo).
- **`factcheck.md`** — every on-screen claim, its source on the live site, and its status.
- **`soundtrack.wav`** — the music bed used in the export. **Placeholder** (see below).
- **`assets/`** — the ten voiceover lines, generated by Koe itself.
- **`.crew/`** — the build workspace: storyboard, images, scripts, built composition.

## The voiceover is the product

`assets/vo-01.mp3` … `vo-10.mp3` were generated by the hosted Koe instance
(`POST /tts` → poll `/job/:id` → `/download/:id`) on the edge engine with
`en-US-EmmaNeural`, using a free key minted for this machine. Ten lines,
94 words — the product narrating its own launch.

The read is a pitch, not a spec sheet: agents have no voice → Koe is where
they get one → what it is → the three moves → no account, no bill → the studio
playground → the claim. The engines line ("Kokoro, Piper, and dozens more")
was cut — as a bare list it broke the flow; `vo-04.mp3` stays on disk unused.

| # | At | Line |
|---|---|---|
| 1 | 1.10 s | Agents can research, write, and ship whole projects. They just can't speak. |
| 2 | 6.05 s | That's where Koe comes in. |
| 3 | 9.00 s | Koe is a text-to-speech server with a host of voice models. |
| 4 | 13.85 s | Point your agent at it. |
| 5 | 17.55 s | Take a free key, connect your agent, and ask for a voiceover. |
| 6 | 23.50 s | No account. No API bill. Nothing to install. |
| 7 | 29.15 s | Or play in the studio — type a line, pick a voice, and hear it. |
| 8 | 34.05 s | A host of voices. One URL. |
| 9 | 37.15 s | Free to start. Give your agent a voice. |

The voiceover is **one continuous read**, not one file per line: `vo-take.mjs` sends the
whole script to the studio as a single paragraph (`assets/vo-take.mp3`, 82 words,
29.57 s), so the prosody never resets between sentences. `mix.mjs` then cuts that take at
its own sentence pauses (they measure an even 0.43–0.47 s) and places the nine pieces on
the beat grid, each trimmed to a fixed 50 ms head / 80 ms tail, at a common −18 LUFS. That
keeps a single performance while still landing every idea on its picture beat. The
engines line is not in the take at all.

The old per-line clips (`assets/vo-01..10.mp3`) are kept on disk for reference but are no
longer used; `vo.mjs` regenerates them only if you want to go back to line-by-line cuts.

Marks live in `.crew/mix.mjs`; each one is set against a visual beat (see
`.crew/beat-sheet.jpg`). The bed ducks ~10 dB under each line via `sidechaincompress`, so
the words sit on top without the track disappearing.

Regenerate the audio and swap it onto the picture without touching the video:

```bash
cd .crew && node vo-take.mjs && node mix.mjs
cd .. && ffmpeg -i koe-en-4k.mp4 -i .crew/mixed.wav -map 0:v -map 1:a \
  -c:v copy -c:a aac -b:a 192k \
  -af "apad,atrim=0:42,afade=t=out:st=41.0:d=1.0" -t 42 -movflags +faststart \
  koe-en-4k.tmp.mp4 && mv koe-en-4k.tmp.mp4 koe-en-4k.mp4
```

`vo-take.mjs` always overwrites `assets/vo-take.mp3`. If you change the script text, also
re-measure the pause cut points with `silencedetect` and update `SEGS` in `mix.mjs`. Both
scripts resubmit a job if the server's edge synthesis fails (a known intermittent
`ENOENT`), which is why a run can log attempts before succeeding. `vo.mjs` is the legacy
per-line generator; it skips clips already on disk, so delete the ones you want re-read.

## Music is a placeholder

`soundtrack.wav` is a 120 BPM bed synthesised locally by `.crew/makebed.mjs`
(kick, hats, sub, a pad and a two-chord stab), then fitted to the beats by
`scripts/soundtrack.mjs`. It is **not** a licensed track and should not ship as
the final score.

Swapping it costs no video re-encode:

```bash
# 1. rebuild the beat grid + bed, 2. remux onto the existing 4K video
cd .crew && node ~/.agents/skills/bs-plush-crew-launch-video/scripts/soundtrack.mjs \
  <new-track.mp3> --beats beats.json --out soundtrack.wav
node -e "..."   # or simply: mix VO over the new bed into mixed.wav, then:
ffmpeg -i ../koe-en-4k.mp4 -i mixed.wav -map 0:v -map 1:a -c:v copy -c:a aac -b:a 192k -shortest out.mp4
```

The ten VO marks in `.crew/mix.mjs` need to stay as they are when a new bed is
fitted — they are cut to the picture, not to the music. Only the `beats.json`
and the bed change.

## Changing the copy or the artwork

```bash
cd .crew
# edit film.json (all on-screen text and image references live there)
node ~/.agents/skills/bs-plush-crew-launch-video/scripts/build.mjs \
  --storyboard film.json --out film --beats beats.json
node ~/.agents/skills/bs-plush-crew-launch-video/scripts/render.mjs film \
  --out ../koe-en-4k.mp4 --resolution 4k --workers 3 --audio mixed.wav --audio-fade 0.05
```

The 4K render runs at roughly 1.3–2.4 fps on this machine. Two Chrome/ffmpeg
instances at once is what makes it fall over on Windows, so render three
14 s chunks **one at a time** and concat them (about 6 min each, ~6 min total
wall clock is not possible — 0–14 s took 342 s, 28–42 s took 183 s):

```bash
cd .crew
for r in "0 14" "14 28" "28 42"; do set -- $r; \
  node ~/.agents/skills/bs-plush-crew-launch-video/scripts/render.mjs film \
    --out ../.chunks/c$1.mp4 --resolution 4k --workers 1 --from $1 --to $2 --crf 16; done
cd .. && printf "file 'C:/.../koe-launch/.chunks/%s.mp4'\n" c0 c14 c28 > .chunks/list.txt
ffmpeg -f concat -safe 0 -i .chunks/list.txt -c copy .chunks/silent.mp4
ffmpeg -i .chunks/silent.mp4 -i .crew/mixed.wav -map 0:v -map 1:a -c:v copy -c:a aac \
  -b:a 192k -af "apad,atrim=0:42,afade=t=out:st=41.0:d=1.0" -t 42 \
  -movflags +faststart koe-en-4k.mp4
```

Note the ffmpeg concat list needs `C:/...` paths (a `/c/...` MSYS path fails),
and the end card carries an optional `end.credit` line (currently `Made with Koe`).

## Template behaviour worth knowing

Between 28.5 s and 30.5 s the engine flashes eight earlier frames (0.25 s each)
as a recap before the end card — that is the engine's own choreography, not a
render fault. It is hardcoded in `film/film.js` (`fbView` in `update()`); change
`if (b >= 57 && b < 61)` there if you want it gone.

## Fact-check

`factcheck.md` lists all 22 claims with sources. Two items are marked
**Illustrative** (`voiceovers/01-hook.mp3` etc. as example output names) and one
sticker is **deliberately false** — the film's own fact-checker strikes it out.
No pricing, uptime, customer or benchmark claims appear anywhere.
