Koe is a hosted MCP server that turns text into a finished voiceover: 29 curated neural voices, no API bill. Point Claude, Cursor, or any MCP client at one URL and it can narrate your video, read a script, or voice a character.

Runs on Microsoft's free consumer endpoint, so it is occasionally throttled and has no SLA. What that means.

Connect your agent

The fastest path is to let your agent configure itself. Pick a manual client below only if you prefer to wire it up yourself.

Let your agent set it up easiest

Copy this whole block into Claude, Cursor, or any agent with MCP support.

You have a Koe TTS MCP server available.

1. Add it as a remote MCP server (Streamable HTTP):
   URL: /mcp
   Header: Authorization: Bearer 
   If you cannot add custom headers, tell me and show me the exact fields to fill in my client.

2. Once connected, call the `studio_status` tool and show me the result.

3. Call `list_voices` and choose a warm male English voice.

4. Call `generate_voiceover` with:
   "Welcome back to the channel. Today we're building something new."
   rate 1.05
   Then download the audio from the returned link and tell me where you saved it.

This prompt contains your key. Treat it like a password and don't paste it into a public repo.

Or configure it by hand

Pick your client. The snippets fill in this page's origin and your key automatically.

Add a custom connector headers are beta

  1. In Claude, open Settings → Connectors → Add custom connector.
  2. Name it Koe TTS and set the URL to /mcp.
  3. Choose No sign-in (Koe is free and has no accounts), then add a request header:
    Authorization: Bearer
  4. Save, then enable the connector in a chat and ask it to call studio_status.

Custom-connector request headers are a Claude beta and may be org-scoped. If your plan does not show them, use Claude Code or Cursor below, which take the header today.

One command

claude mcp add --transport http koe-tts /mcp \
  --header "Authorization: Bearer "

Then run /mcp to confirm koe-tts is connected, and ask: "Call studio_status."

Requires Claude Code with HTTP transport support.

Global or project config

Add this to ~/.cursor/mcp.json (or .cursor/mcp.json in a project), then restart Cursor.

{
  "mcpServers": {
    "koe-tts": {
      "url": "/mcp",
      "headers": {
        "Authorization": "Bearer "
      }
    }
  }
}

Cursor's MCP settings UI has the same fields if you prefer clicking.

Streamable HTTP, stateless

Any MCP client that supports remote HTTP servers can connect:

FieldValue
Transportstreamable-http
URL/mcp
HeaderAuthorization: Bearer
Alt headerx-api-key:
ResponsesJSON (no SSE required)

The endpoint is stateless: every request is independent, so it works behind load balancers and serverless hosts.

Run the MCP server locally

Prefer a local process, or need a file path in your project? The repo ships the same tools over stdio. It talks to this studio and saves audio to your disk.

cd mcp && npm install
TTS_STUDIO_URL= node index.js

Add it to claude_desktop_config.json with command: "node" and args: ["/path/to/mcp/index.js"]. On Windows PowerShell, set the URL with $env:TTS_STUDIO_URL="..." or put it in the config's env. It mints and stores its own free key in ~/.koe/credentials.json. Full reference: AGENTS.md.

Tools

Six tools. Voice generation is metered per key; the rest are free.

ToolWhat it does
studio_statusHealth, available engines, queue depth, and your current quota.
list_voicesCurated neural voices with language, gender, and style; optional language filter.
generate_voiceoverText to audio. Returns a short-lived signed download URL and inline audio for short clips.
get_voiceover_statusPoll a job by id when a long script is still generating.
list_recent_voiceoversYour 10 newest jobs (tenant-isolated).
get_usageRequests and words used this hour and today, limits, and reset times.

Free by architecture

No accounts, no card, no permanent storage. Per-key limits, a bounded queue, and ephemeral audio are how one small instance stays free for everyone.

Troubleshooting

The errors you are most likely to hit, in the order you are most likely to hit them.

401 — API key required or invalid

Send the key as Authorization: Bearer koe_sk_… or x-api-key: koe_sk_…. If the operator rotated KOE_SECRET, old keys stop verifying; create a new one above, or paste an existing key under “Already have a key?”.

The connector is connected but tools never run

Enable the connector for the current chat, then ask explicitly: “Call the studio_status tool from Koe TTS.” Some clients require per-tool approval the first time.

429 — Hourly or daily word limit reached

You have used your free window. The response includes retryAfterSeconds; get_usage shows when it resets. Failed jobs refund their words.

410 — Audio expired

Generated audio is ephemeral (about 15 minutes). The download link only works while the file exists; generate again, or keep the file your agent already saved.

The first call takes about 60 seconds

The free host sleeps after about 15 minutes idle. The MCP client waits it out; subsequent calls are fast. No action needed.

503 — Engine “piper” is not available

The offline engine is optional. Use engine: "edge", which is always available and higher quality.

Is edge-tts an official Microsoft API?

No. Koe uses Microsoft's free consumer endpoint through the open-source edge-tts client. It is not affiliated with Microsoft, it can be throttled, and it has no SLA. For production guarantees, use a paid speech API or self-host Piper.

Why did opening /mcp in a terminal return text?

GET /mcp is a browser setup page; MCP clients use POST /mcp. Opening the URL in a terminal returns a short text note instead of the page. That is expected.

Do you support OAuth or one-click directory install?

Not yet. Koe has no accounts, so a free signed key is the identity. Static-header connectors (Claude beta, Cursor, Claude Code) work today; an OAuth consent flow is on the roadmap.
